# RAG Agent Studio 技术文档

> 检索质量 ≈ 切块质量 × 检索策略 × 排序质量 × Query 质量。四项相乘，任何一项是短板，整体就不行。

本文从五个方面介绍 RAG Agent Studio：产品定位、功能、架构、调优、页面导航。调优一章按《RAG优化指南》的六个阶段展开，每一条都对应到本项目的参数和页面。代码位置以 `prism/`、`app/`、`frontend/` 为准，参数名以 `config.yaml` 为准。

---

## 一、产品定位

### 1.1 它是什么

RAG Agent Studio 是一套**可运行、可观察、可评测**的 RAG（检索增强生成）全栈参考实现。它把 RAG 实战里的方法论做成了一条完整的链路：

**MinerU 4.x 解析 → MinerU-Popo 文档树 → 清洗 → 语义感知切片 + Parent-Child → 向量 + BM25 + HyDE 多路召回 → RRF 融合 → Reranker 精排 → Small-to-Big → 回答协议 → 评测闭环**

在这条主链路之外，还有语料覆盖分析与治理、多模态（文搜图 / 图搜图 / 图搜文）、LanceDB 应用（长期记忆 / 推荐 / 多智能体 / Agent 湖）和飞书文档接入。

### 1.2 解决什么问题

| 常见痛点 | 本项目的做法 |
| --- | --- |
| RAG 效果不好，不知道问题出在哪一层 | 检索实验室把查询层 → 召回 → 融合 → 精排 → 上下文每一层都摊开；评测中心按层消融、归因 |
| 调参全凭感觉，改了不知道好没好 | 黄金集 + Hit / MRR / NDCG + 历史报告，每改一个变量跑一次 |
| 文档解析把结构丢了，后面全是补救 | MinerU 四档 + Popo 文档树：跨页表格、标题层级、图文关联 |
| 语料本身有缺口、有噪音 | 语料覆盖（意图 × 知识）、质量体检、FAQ 增强、别名词典、自动元数据 |
| 图表、截图里的信息检索不到 | 一张图三份索引（CLIP 向量 / 描述向量 / 描述 BM25），OCR 保版面 |
| 企业文档在飞书里，没法同步进知识库 | 飞书文档按版本增量同步、自动同步、文档智能体读写 |

### 1.3 适合谁

- **RAG 工程师**：拿它当调优台，逐层看、逐层调、逐层测。
- **企业知识库 / 客服 / 合规团队**：策略配置页的四个场景预设（企业综合知识库 / 医疗·法律 / 客服 FAQ / 长文档问答）直接起步。
- **学习 RAG 的人**：每个能力都有代码位置、参数和实测数字。

### 1.4 运行形态

- 不配任何模型也能完整操作（离线模式：哈希向量 + BM25 + 词法精排 + 抽取式回答）。
- 配上模型后获得真实语义：默认 BGE-M3 向量、bge-reranker-v2-m3 精排、Anthropic 或 OpenAI 兼容端点的文本模型。
- 单机运行，SQLite 存元数据，索引落在本地目录；可选 LanceDB / Qdrant / Chroma 作向量后端。

## 二、功能

### 2.1 离线入库

| 环节 | 做什么 | 代码 |
| --- | --- | --- |
| 解析 | MinerU 4.x 四档（flash / basic / standard / advanced）本机、云端或自托管；未装 MinerU 时自动用 pdfplumber / python-docx / python-pptx；Markdown 直解析；Excel / CSV 行级结构化 | `prism/ingest/parsers/` |
| 文档树 | MinerU-Popo：跨页表格合并、段落续接、全文标题层级重建、图文关联 | `prism/ingest/popo_bridge.py` |
| 清洗 | 页眉页脚（同一行出现在 ≥ 40% 页面）、PDF 断行、乱码、近重复 | `prism/ingest/cleaning.py` |
| 切片 | structural（标题面包屑，默认）/ semantic / recursive；表格、代码、公式原子块不拆；超长表格按行拆并重复表头 | `prism/ingest/chunking/` |
| Parent-Child | child 150 token 用于检索，parent 600 token 用于阅读 | `prism/ingest/chunking/parent_child.py` |
| 增强 | Contextual Retrieval 上下文摘要、假设性问题（可选，入库期每块一次 LLM 调用） | `prism/ingest/enrich.py` |
| 索引 | 向量（numpy / LanceDB / Qdrant / Chroma）+ BM25（bm25s + jieba）+ 实体图（UnWeaver）+ SQL 表（Excel / CSV → SQLite） | `prism/index/` |
| 自动重建 | 换向量模型或改入库参数后，服务在后台重建受影响的知识库；新索引建在暂存目录，建好后原子替换，线上检索不受影响 | `app/services/reindex_service.py` |

### 2.2 在线检索与生成

| 层 | 做什么 | 关键参数 |
| --- | --- | --- |
| 查询层 | 多轮归并、改写、Multi-Query、分解、HyDE（含编号 / 数字时自动跳过）、元数据自查询；各项并发调用、关闭模型思考 | `retrieval.query_transform.*`、`retrieval.metadata_filter.*` |
| 多路召回 | 向量、BM25、HyDE、SQL 结构化检索并发执行，每路 top-50 | `retrieval.top_n_per_route`、`retrieval.sql.*` |
| 融合 | RRF（k=60）或凸组合；多查询 × 多路一起融合（RAG-Fusion） | `retrieval.fusion.*` |
| 精排 | 本地交叉编码器 / Cohere / Rerank API / LLM 打分 / 词法；候选 ≥ 50，保留 10 | `retrieval.rerank.*` |
| 多样化 | MMR（可选） | `retrieval.diversify.*` |
| 粒度 | child → parent、相邻合并、Lost-in-the-Middle 排序，最终 3–5 段 | `retrieval.granularity.*` |
| 织网 / 压缩 | UnWeaver 术语定义织入；规则 / LLM 上下文压缩 | `retrieval.graph.*`、`retrieval.compression.*` |
| 多跳 / Agentic / 路由 | 一次检索拿不全证据时多跳；跨库自动路由，路由选中的库答不上时自动换库 | `retrieval.multihop`、`retrieval.agentic`、`retrieval.router` |
| 生成 | 回答协议：依据 / 拒答 / 冲突 / 安全 / 格式 + 引用 [n]；SSE 流式 | `generation.*` |

### 2.3 语料准备与治理

- **语料覆盖**：意图空间 × 知识空间，每条意图分到高匹配 / 部分匹配 / 无匹配，给出缺失关键词；找出未被任何意图命中或已过期的文档。
- **质量体检**：段落级（乱码 / 目录页 / 短段 / 超长 / 重复 / 近似重复）与文档级（过期 / 多版本同时生效 / 无切片 / 缺元数据）问题，按内容指纹剔除，重建后仍生效。
- **覆盖增强**：为覆盖缺口由模型根据检索到的原文写 FAQ 草稿，人工审核后发布为普通文档。
- **别名词典与关键词扩展**：缩写 ↔ 全称、口语 ↔ 书面语；可从语料里自动发现候选。
- **自动元数据**：上传时抽取标题 / 版本 / 生效区间 / 部门 / 标签 / 密级，只填空字段。

### 2.4 多模态

- 入库：从 PDF / Word / PPT / Markdown / 图片抽取图片，记录页码、图注、邻近正文；OCR 取图中精确文字（保留版面：同列文字归成一组），VLM 生成语义描述；一张图三份索引。
- 检索：文搜图、图搜图、图文混合（α 加权消除模态间隙）、图搜文；各路 RRF。
- 问答：回答自动附图（有门槛，不相关的问题不挂图），用 [图n] 引用；上传图片可以图搜图 / 以图搜文 / 看图问答。
- 实测：1000 张合成图表入库 261s，文搜图 ~55ms，命中率 100%；真实英文论文（43 张图表）开 VLM 描述后文搜图 hit@1 0.85。

### 2.5 LanceDB 应用

| 能力 | 做什么 |
| --- | --- |
| 向量后端 | `vector_store.backend: lancedb`，小表精确扫描，≥ 2 万行自动建 IVF_HNSW_SQ；原生全文（ICU 中文分词）可替换 BM25 |
| 长期记忆 | 按用户记住身份 / 偏好 / 事实；召回分 = 0.7·相似度 + 0.15·新近度 + 0.15·重要度；回答后后台抽取、去重合并 |
| 个性化推荐 | 兴趣向量 = 交互条目向量的时间衰减加权和；热度加分、MMR 去同质化，每条推荐带理由 |
| 多智能体 | 规划 → 并行研究 → 分析 → 审校（证据不足改写重查）→ 撰稿；共享黑板，运行可回放 |
| Agent 湖 | 每轮问答沉淀为带版本的宽表：检索增强（召回相似历史问答）、检索质量 / 知识缺口分析、缺口复测、问题主题、只读 SQL、湖目录、分析智能体；版本 / Tag / 分支 / 派生列 |

### 2.6 飞书文档

| 能力 | 做什么 |
| --- | --- |
| 同步进知识库 | 粘贴 docx / wiki 链接或从文件夹勾选；块转 Markdown（标题、列表、待办、代码、表格）；图片下载后 OCR + VLM 描述写进正文；按 `revision_id` 增量，没改过的跳过 |
| 自动同步 | 定时（`auto_sync_minutes`）后台线程对所有接入知识库增量同步；事件订阅（`drive.file.edit_v1`）收到后只同步那一篇 |
| 查看 | 按飞书原样排版展示（标题字号、颜色、列表编号、表格列宽、原图） |
| 增删改查 | 新建（可直接入库）、追加、整篇替换、查找替换（保留样式）、删除；改过的文档自动重新同步 |
| 文档智能体 | 自然语言查询 / 总结 / 对比 / 修改飞书文档；知识库里的上传文档也能读、能原样写进飞书；写操作默认待确认 |

### 2.7 评测

黄金集（JSONL）→ 分阶段消融（仅向量 / 仅 BM25 / 融合 / 完整链路）→ Hit@K / MRR / NDCG → 错误归因 → 历史报告。多模态评测另有文搜图 / 图搜图 Hit@K、回答附图精确率 / 召回率。

### 2.8 模型与部署

- **模型配置中心**：文本 / 嵌入 / 重排 / 多模态 / 图文向量五类自由组合；Anthropic SDK、OpenAI 兼容端点、本地 sentence-transformers、Rerank API；拉取模型列表、连接测试。激活的配置优先于 `config.yaml`。
- **辅助模型**：查询改写 / HyDE / text-to-SQL / 路由用快速模型（`generation.llm.aux_model`），关闭思考。实测查询层 9–12 秒 → 0.7–1.1 秒。
- **部署**：`deploy/server.sh` 一键安装 systemd + Nginx，可设访问密码；`deploy/install-deps.sh` 装依赖。
- **命令行**：`rag ingest / query / ask / coverage / eval / popo-export / serve`。

## 三、架构

### 3.1 总体结构

```
frontend/   React 19 + Vite + TypeScript —— 16 个页面，/api 代理到后端
   │  HTTP / SSE
app/        FastAPI —— api/ 路由（16 组）、services/ 业务、db/ SQLite 元数据
   │
prism/      核心库，不依赖 Web —— ingest / index / retrieval / generation / eval / corpus / multimodal / lance / lake / feishu
   │
data/       uploads/ 原文件 · indexes/<kb>/ 每库一个索引 · lancedb/ 全局库 · app.db 元数据 · feishu_media/ 飞书图片缓存
```

三层职责分明：`prism` 是纯 Python 库，CLI 直接调用它；`app` 把它包成服务并管理知识库 / 文档 / 配置的生命周期；`frontend` 只通过 HTTP 与后端交互。

### 3.2 离线入库管线

```
文档 ─▶ 解析 ─▶ (Popo 文档树) ─▶ 清洗 ─▶ 结构 / 语义切片 ─▶ Parent-Child ─▶ 增强 ─▶ 索引
       MinerU 4.x / Markdown /    跨页表格合并     页眉页脚 / 断行    标题面包屑        child 150 tok    上下文摘要    向量 + BM25
       Excel 行级 / docx / pptx   段落续接          乱码 / 近重复      表格代码原子块    parent 600 tok   假设性问题    + 实体图 + SQL 表
```

入库参数（解析 / 清洗 / 切片 / 增强 / BM25 / 向量库）会进入索引指纹；指纹变了，服务自动重建。重建在 `data/indexes/.<kb>.rebuild-staging` 进行，建好后把重建期间的改动补进去，再用两次目录改名原子替换；进程被打断时正式索引从未被动过。

### 3.3 在线检索漏斗

```
用户 Query
  │ 查询层   多轮归并 / 改写 / Multi-Query / 分解 / HyDE / 元数据自查询（并发，关思考）    retrieval/query_transform.py
  ├─ 向量检索（每条查询 top-50）                                                   index/vector_store.py
  ├─ BM25（jieba + 精确 token 保护，top-50）                                       index/bm25_store.py
  ├─ HyDE 假设文档 → 向量检索
  └─ SQL 结构化检索（Excel / CSV → SQLite；只读 text-to-SQL 或规则兜底）            index/table_store.py
  ▼ 融合层   RRF k=60 → 候选 ≥ 50                                                  retrieval/fusion.py
  ▼ 精排层   Cross-Encoder / Rerank API / LLM / 词法 → 10                          retrieval/rerank.py
  ▼ 多样化   MMR λ=0.7（可选）                                                     retrieval/diversify.py
  ▼ 粒度层   child → parent、相邻合并、Lost-in-the-Middle 排序 → 3~5               retrieval/granularity.py
  ▼ 织网层   UnWeaver 术语定义织入（可选）                                         graph/unweaver.py
  ▼ 压缩层   规则 / LLM 上下文压缩（可选）                                         retrieval/compress.py
  ▼ 生成层   回答协议：依据 / 拒答 / 冲突 / 安全 / 格式 + 引用                      generation/
```

漏斗的数字是：每路 50 → 候选 ≥ 50 → 精排保留 10 → 上下文 3–5 段。

### 3.4 多模态管线

```
入库   抽取图片（页码、图注、邻近正文；过滤图标与每页重复的 logo）──▶ OCR + VLM ──▶ 一张图三份索引：
       图文向量（CLIP 图像塔）· 图片文本摘要的文本向量 · 图片文本摘要的 BM25；图片挂到所在的 parent 块

文搜图   text ─▶ CLIP 文本塔 ＋ 描述向量 ＋ 描述 BM25 ─▶ RRF
图搜图   image ─▶ 图像塔（余弦相似度）
图文混合 score = α·z(text·I) + (1-α)·z(image·I)
图搜文   image ─▶ 图文向量直达正文 ＋ 相似图片所在段落 ＋ OCR / VLM 转文字再检索 ─▶ RRF ─▶ Small-to-Big
```

### 3.5 数据与存储

| 存储 | 内容 |
| --- | --- |
| SQLite `data/app.db` | 知识库、文档、飞书文档关联、模型配置、会话与消息、策略覆盖、评测报告（8 张表） |
| `data/indexes/<kb_id>/` | 每个知识库一个索引目录：向量、BM25、块存储、图片索引、实体图、SQL 表 |
| `data/lancedb/` | 全局 LanceDB：长期记忆、推荐、多智能体黑板、Agent 湖、知识库镜像 |
| `data/uploads/<kb_id>/` | 原文件；飞书文档同步为 `.md`，图片在 `feishu-assets/` |
| `data/feishu_media/` | 飞书图片缓存与 OCR / 描述结果 |

配置分两层：`config.yaml` 是策略基线，前端「策略配置」页的覆盖保存在 SQLite，不改文件。

### 3.6 模型层

| 类型 | 默认 | 可选 |
| --- | --- | --- |
| 文本模型 | Anthropic（`claude-opus-5-5`） | OpenAI 兼容端点（DeepSeek / Qwen / vLLM / Ollama…）；辅助模型可单独指定 |
| 嵌入 | BAAI/bge-m3（1024 维，本地） | OpenAI 兼容 embeddings；无模型时哈希向量 |
| 重排 | BAAI/bge-reranker-v2-m3（本地交叉编码器） | Cohere Rerank、Jina / SiliconFlow API、LLM 打分、词法 |
| 多模态 | 无 | 能看图的模型，用于图片描述与看图回答 |
| 图文向量 | Chinese-CLIP（本地） | Jina 兼容 API；离线感知特征（只支持图搜图） |

Apple Silicon 上本地模型共用一把 GPU 锁串行执行（MPS 不是线程安全的）；服务启动后台预热模型。

### 3.7 后端 API

前缀 `/api/v1`，共 16 组路由：

| 路由 | 用途 |
| --- | --- |
| `knowledge-bases`、`documents` | 知识库与文档的增删改查、上传、切片预览、Markdown 校对回灌、重新解析 |
| `retrieval`、`chat` | 检索实验室、流式问答（SSE） |
| `multimodal` | 图文检索、图片库、能力状态 |

### 3.8 测试

`tests/` 是离线的单元 + API 端到端测试：不加载本地大模型（哈希向量、词法精排），数据库指到临时目录，飞书开放平台用内存里的假服务（`httpx.MockTransport`）模拟。`pytest` 不需要模型与网络。

## 四、调优

调优顺序：**语料 → 切片 → 混合检索 → 重排 → Query 改写**。每改一个变量在「评测中心」跑一次，指标不动就不合入。下面按《RAG优化指南》的六个阶段，把每条策略对应到本项目的参数与页面。

### 4.1 数据入库与预处理（检索的"底座"）

**文档解析**

| 指南建议 | 本项目 |
| --- | --- |
| 多格式解析，提取净文本，OCR 处理扫描件 | MinerU 四档：数字文档建索引用 `flash`（默认，CPU 即可）；扫描件 / 表格 / 公式用 `basic`；复杂版面用 `standard`；小机器走云端（`parsing.mineru.mode: cloud`） |
| 跨页表格合并、跨页段落拼接、标题层级重建、图文归属 | MinerU-Popo：知识库页对 PDF 点「Popo」导出输入 → `scripts/run_popo.sh` → 打开 `parsing.popo.enabled` → 重新解析 |
| 内容清洗：乱码、冗余、非打印字符 | `cleaning.*`：页眉页脚比例 0.4、PDF 断行修复、近重复 Jaccard 0.9、乱码比例 0.3；清洗对全文做，不对单块做 |

实测：`flash` 档对英文学术 PDF 的图片检索反而比 `standard` 好（flash 附带图中文字转写）；开 VLM 描述时两档差别很小。

**切片（约一半的调优时间在这里）**

| 指南建议 | 本项目参数 | 推荐值 |
| --- | --- | --- |
| chunk_size 从 800 字符起 | `chunking.parent_max_tokens` | 500–800 token（中文 300–500 字），默认 600 |
| overlap 10%–20% | `chunking.child_overlap_ratio` | 0.10–0.15，默认 0.12 |
| Parent-Child：小块检索、父块阅读 | `chunking.child_tokens` / `parent_max_tokens` | child 100–150 / parent 500–800 |
| 结构分块：按标题层级 | `chunking.strategy: structural`（默认） | 标题面包屑随块保存 |
| 语义分块：相邻句相似度断点 | `chunking.strategy: semantic`、`semantic_breakpoint_percentile` | P80 |
| 表格 / 代码不拆 | `chunking.respect_atomic_blocks: true`、`table_row_split_tokens: 800` | 超长表格按行拆、每块重复表头 |

在「知识库 → 切片」里看 parent / child 是否语义完整、表格是否带表头、面包屑是否正确。

**语料增强与索引增强**

| 指南建议 | 本项目 |
| --- | --- |
| Doc2Query 反向提问 | `enrich.hypothetical_questions: true`、`questions_per_chunk: 3`（入库期每块一次 LLM 调用） |
| 摘要索引 | `enrich.contextual_summary: true`（Contextual Retrieval） |
| 图增强（Graph RAG） | `retrieval.graph.unweaver_enabled`：实体定义织入，`max_weaved: 3`，织入块也过精排 |
| 元数据过滤 | 上传时自动元数据；`retrieval.metadata_filter.mode: llm`，从问题里读出年份 / 部门 / 标签 / 文件类型先缩小范围；`filter_expired` 过滤过期语料 |
| 先知道用户会问什么 | 「语料覆盖」页：意图 × 知识；「语料治理」页：为缺口生成 FAQ、别名词典、质量体检 |

### 4.2 检索前优化（查询层）

| 指南建议 | 本项目参数 | 说明 |
| --- | --- | --- |
| 查询重写：口语 → 书面、术语对齐 | `retrieval.query_transform.rewrite: true` | 别名词典的查询扩展也在这一层生效 |
| Multi-Query 3–5 条 | `multi_query: 3`，原始问题始终保留 | 多查询 × 多路一起 RRF（RAG-Fusion） |
| HyDE | `hyde: true`、`hyde_max_query_chars: 30`、`skip_hyde_on_precise_tokens: true` | 含编号 / 数字 / 日期时跳过，否则是反模式 |
| 查询路由 | `retrieval.router.enabled`、`mode: embedding \| llm` | 跨库路由；选中的库答不上时自动换库（页脚显示「路由兜底」） |
| Step-Back | `step_back: false` | 复杂推理问题再开 |
| 多轮指代消解 | `condense_history: true` | 多轮问答先归并历史 |

性能要点：这些调用互不依赖，并发执行；一律关闭模型思考，否则推理模型把 `max_tokens` 花在思考上、直接返回空。`generation.llm.aux_model` 换成快速模型（如 deepseek-flash）后，查询层 0.7–1.1 秒。

### 4.3 检索中优化（召回与融合）

| 指南建议 | 本项目参数 | 推荐值 |
| --- | --- | --- |
| 混合检索：向量 + BM25 | 向量路 + `sparse_backend: bm25`（或 `lancedb_fts`） | 每路 `top_n_per_route: 50`（50–100，比最终 top-K 大 5–10 倍） |
| 融合：RRF | `fusion.method: rrf`、`rrf_k: 60` | RRF 只看排名、零调参；凸组合 `convex_alpha` 需评估集 |
| 关键词权重 | `fusion.weight_sparse` | 金融 / 法律 / IT 文档可调高到 1.5 |
| BM25 参数 | `sparse.k1: 1.5`、`b: 0.75` | 长文档 k1 2.0；文档长度均匀 b 0.5 |
| 领域词、编号 | `sparse.user_dict`、`exact_token_boost` | 编号 / 错误码类查询靠 BM25 命中 |
| 嵌入模型选型 | `embedding.model: BAAI/bge-m3`（1024 维） | 换模型后自动重建；向量规模百万以内 768 维够用，术语密集用 1024 维，维度一旦定下不要随意换 |
| 微调嵌入 | `rag mine-negatives` + `prism.training.finetune` | 最后才动模型，而且要独立评测验收 |
| 结构化数据 | `retrieval.sql.enabled`：Excel / CSV → SQLite，只读 text-to-SQL | 混合检索的第三路 |
| 元数据过滤 | `retrieval.metadata_filter.*` | 先过滤再算相似度 |

实测（示例黄金集，只看向量路）：哈希向量 Hit@1 0.786 → BGE-M3 0.929。口语问法 BM25 排第一的是无关文档，BGE-M3 直接命中。

### 4.4 检索后优化（精排与后处理）

| 指南建议 | 本项目参数 | 推荐值 |
| --- | --- | --- |
| 交叉编码器精排 | `rerank.provider: auto`，默认 bge-reranker-v2-m3 | 候选 `candidates: 50`（低于 50 效果断崖式下跌），`keep_n: 10` |
| LLM 重排 | `rerank.provider: llm` | 一次十秒量级，只在精度要求极高时用 |
| 拒答阈值 | `rerank.min_score` | bge-reranker-v2-m3 取 0.02–0.05（无关对 < 0.01，同义改写 0.1–0.2）；换模型重测 |
| 相对阈值 | `rerank.min_score_ratio: 0.5` | 低于 top-1 × 0.5 的不进上下文 |
| 上下文压缩 | `compression.enabled`、`mode: rule \| llm`、`ratio: 0.6` | 块又长又吵时开 |
| 合并去重、段落连贯 | `granularity.return_parents`、`auto_merge_adjacent`、`max_context_tokens: 3000` | Small-to-Big + 相邻合并 |
| MMR 多样化 | `diversify.enabled`、`mmr_lambda: 0.7` | top-K 都是同一段时开 |
| 最终 top-K | `rerank.top_k: 5` | 3–5，Lost in the Middle 排序 |

实测：bge-reranker-v2-m3 在 Apple Silicon 上 50 个候选约 0.2 秒；黄金集可答题精排最高分 0.79–0.999，库外问题 ≤ 0.002，阈值 0.03 时命中率不变、无答案题全部拒答。

### 4.5 生成阶段优化

| 指南建议 | 本项目 |
| --- | --- |
| 严格基于上下文、无资料直接说明 | 回答协议（依据 / 拒答 / 冲突 / 安全 / 格式）；`generation.refuse_when_no_context: true` |
| 引用溯源 | `cite_sources: true`：回答带 [n]，前端可点击定位；带图回答用 [图n] |
| 自我反思 | 多智能体的审校环节：证据不足改写重查 |
| 模型调参 | `generation.llm.effort`、`max_tokens: 4096`、`thinking: auto`（普通问答不思考，多跳 / Agentic 才思考） |

实测：`thinking: auto` 后普通问答首字 3.4–5.5 秒 → 0.5–1.3 秒，回答同样正确并带引用。

### 4.6 进阶与系统级优化

| 指南建议 | 本项目 |
| --- | --- |
| 难负样本微调 | `rag mine-negatives` 从生产索引挖难负例，重排模型剔除伪正例，`--distill-weight` 蒸馏教师分；`python -m prism.training.finetune` 训练，独立评测验收 |
| 动态检索与反馈回路（CRAG） | 多跳（`multihop`）、Agentic（`agentic`）；路由兜底自动换库；Agent 湖的缺口复测 |
| 多轮对话与记忆 | `condense_history` 指代补全；长期记忆按用户召回（只用于个性化，不作事实依据） |
| 历史问答复用 | Agent 湖检索增强：召回余弦 ≥ 0.75 的历史问答作参考，排除点踩 / 拒答 |

### 4.7 诊断表

出问题先找层，再找参数：

| 症状 | 先查 | 改什么 |
| --- | --- | --- |
| 答案在库里，任何一路都没召回 | 知识库页切片预览：答案是否被切到两块 | `chunking.parent_max_tokens`、`strategy`；面包屑是否存在 |
| 同义问法找不到 | 消融：sparse 有 dense 没有 | 上下文摘要、假设性问题、换 embedding |
| 编号 / 型号 / 错误码找不到 | 消融：dense 有 sparse 没有 | `sparse.user_dict`、别名词典、`exact_token_boost`；确认 HyDE 被跳过 |
| 找到了但排第 3–5 | fused 有 reranked 没有 | `rerank.candidates` ≥ 50；换重排器 |
| 库里没答案却编了一个 | 精排 top-1 分数 | `rerank.min_score` 0.02–0.05；`refuse_when_no_context` |
| 新旧版本反复横跳 | 文档是否填了生效 / 失效日期 | 元数据；`filter_expired`；自查询 `year` |
| top-K 都是同一段 | 是否开了 `auto_merge_adjacent` | `diversify.enabled` + `mmr_lambda: 0.7` |
| 资料对但答错 | 回答是否引用了正确块 | 提示词、`effort`、换模型 |
| 首字慢 | 链路里哪一层耗时长 | 辅助模型关思考；`thinking: auto`；候选 50 → 30 |
| 内存不够 | 本地重排 2.3 GB + bge-m3 | `RAG_DISABLE_LOCAL_RERANKER=1` 改词法 / API 重排；MinerU 改云端 |

### 4.8 场景预设

「策略配置」页顶部一键填入，只改 `retrieval` 段：

| 场景 | 组合 |
| --- | --- |
| 企业综合知识库 | 混合检索 + RAG-Fusion + 重排 |
| 医疗 / 法律 / 合规 | 不做 HyDE 和 Multi-Query、BM25 权重 1.5、相对阈值 0.5、压缩、过期一律过滤 |
| 客服 FAQ | 改写 + 双路 + 重排只给 3 条 |
| 长文档问答 | 父块返回 + 压缩 + MMR |

"瓶颈 → 手段"对照：查不全 → 混合检索 / 多路召回；查不准 → RRF + 重排；块又长又吵 → 上下文压缩；答不对 → 父块与切片。手段不是全上最好，选 3–5 种组合，用评测集 A/B。

### 5.4 顶栏

- **用户**：切换当前用户（为空时为 default），长期记忆与推荐按它区分。
- **部门**：权限过滤用。
- **知识库选择**：大多数页面按当前知识库工作。

### 5.5 一条典型的使用路径

1. **模型配置**：添加文本模型、嵌入、重排并激活（或先不配，走离线模式）。
2. **知识库**：新建知识库、上传文档（或在**飞书文档**里接入）；在「切片」里看 parent / child 是否完整。
3. **语料覆盖 → 语料治理**：确认库能回答用户会问的问题；剔除噪音、补 FAQ、补别名。
4. **检索实验室**：拿几个典型问题逐层看；右侧改参数做 A/B。
5. **策略配置**：把验证过的参数保存下来（或先用场景预设）。
6. **评测中心**：维护黄金集（≥ 100 条：50% 常见 / 30% 长尾 / 20% 多跳），每改一个变量跑一次。
7. **智能问答**：最终效果；**Agent 湖**：上线后看知识缺口，补语料后复测。
